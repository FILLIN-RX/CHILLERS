# iOS/Android download fix: window.open() replacement

iOS Safari downloads were failing with the hidden iframe approach. The fix replaces iframe navigation with `window.open()` + automatic tab closure after 2 seconds. Safari detects the `Content-Disposition: attachment` header and triggers its native download manager while the tab closes in the background. The download continues independently.

**Watch for:** No user feedback on iOS after download triggers (confirmed), console logs verbose enough to spam production (confirmed), misleading "triggering native download" log fires after Blob is complete (confirmed).

**Verdict**: APPROVED

---

## High-level view

The core change swaps hidden iframe for `window.open(href, '_blank')` with a 2-second auto-close timer. If the popup is blocked, the code falls back to the old iframe approach. iOS detection routes all third-party URLs through `/api/download/file` which sends `Content-Disposition: attachment`. Android behavior splits between StreamSaver (with service worker) and native Blob download (without service worker), unchanged from before. Desktop continues using StreamSaver with MITM iframe. The backend already sent the correct headers, so no backend changes were required beyond adding debug logs. Tests were updated to mock `window.open()` and verify the close timer fires after 2000ms.

## window.open() with auto-close and fallback

`triggerAttachmentDownload()` in `src/services/downloads.ts` now calls `window.open(href, '_blank')` instead of creating a hidden iframe. When the window reference is returned, a 2-second `setTimeout` closes it. The tab closure is wrapped in try-catch because Safari can throw if the window is already gone or if the script loses permission to close it.

If `window.open()` returns null — popup blocked by browser settings or extension — the code logs a warning and falls back to creating the old hidden iframe. The iframe persists for 2 minutes before being removed, matching the old behavior. This fallback is a safety net but represents degraded UX since hidden iframes are what iOS Safari started blocking in the first place.

## iOS branch in streamSaver

The iOS detection branch in `src/services/streamSaver.ts` calls `toIOSDownloadHref()` to route third-party URLs through the backend proxy, then calls `triggerAttachmentDownload()` with the proxied URL. Five new console.log statements trace the flow: iOS detected, backend origin, constructed href, before trigger, after trigger.

The function returns `{ totalBytes: null, iosTriggered: true }` immediately after triggering the download. The `iosTriggered` flag signals to the caller that the download was handed off to Safari's native manager and no progress tracking is available.

## Android Blob fallback preserved

The Android Chrome path without service worker (lines 142-186 in `streamSaver.ts`) remains unchanged except for one additional console.log after the Blob is created. This path is only hit when `isAndroidMobileChrome()` returns true and `navigator.serviceWorker.controller` is null.

The new log prints the filename and total bytes received. The wording "triggering native download" is misleading — the download is already complete at this point, the log fires after the Blob is assembled.

## Backend headers confirmed

The backend routes `/api/download/file` and `/api/download/stream` both set `Content-Disposition: attachment` with properly encoded filename. The commit adds console.log statements in both routes that print the header and filename. The headers were already correct before this commit — the iOS issue was on the client side (iframe vs window.open), not the server side.

## Test coverage

The test file `src/services/__tests__/download.test.ts` was updated with a new test suite `describe('triggerAttachmentDownload()')` covering:

- `window.open` is called with the correct href and `'_blank'` target
- `win.close()` is called after exactly 2000ms using `jest.useFakeTimers`
- Blocked popup: `window.open` returns null, fallback iframe is created, warning is logged
- Close error: `win.close()` throws, error is caught and logged with `console.warn`
- Empty href: no-op, `window.open` not called

The existing iOS tests in the `streamDownloadToDisk` suite were updated to mock `window.open` and check for `iosTriggered: true` in the result.

All tests pass. TypeScript compiles successfully.
