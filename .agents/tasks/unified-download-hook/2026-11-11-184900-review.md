# Unified Download Hook for iOS Production Fix

Centralizes download logic into `useUnifiedDownload` hook that fixes iOS production bug where downloads opened `chillers.site` (frontend) instead of Railway backend. The root cause was relative URLs like `/api/download/file?...` resolving to the current domain in production. The fix ensures all iOS downloads use absolute backend URLs via `getBackendOrigin()`.

The implementation adds a new hook (334 lines), comprehensive tests (605 lines, 21 test cases), updates the service layer to build absolute URLs, and integrates the hook into all three download call sites (VideoPlayer, DownloadModal, useDownloadsBatch). All tests pass, build succeeds with no TypeScript errors.

**Watch for:** none — the iOS URL construction fix is confirmed (3 uses of `getBackendOrigin` in hook + 2 in service layer), integration is complete across all call sites, tests comprehensively verify absolute URL construction, and build/tests pass cleanly.

**Verdict**: APPROVED

## High-level view

The new `useUnifiedDownload` hook centralizes platform detection and routes downloads through platform-specific paths: iOS uses `window.open()` with absolute backend URLs (fire-and-forget), while Desktop/Android use `streamDownloadToDisk` with progress tracking and cancellation. The critical fix is the `buildAbsoluteUrl` helper that prepends `getBackendOrigin()` to any relative path before passing to `window.open()`, ensuring iOS navigates to `https://chillers-production-eace.up.railway.app/api/download/...` instead of `https://chillers.site/api/download/...`.

The service layer (`downloads.ts`) received parallel fixes: `toIOSDownloadHref` now returns absolute URLs with `getBackendOrigin()` when proxying third-party downloads, and `triggerAttachmentDownload` converts relative URLs to absolute before opening. This provides defense in depth — the hook handles URL construction, but the service layer also protects direct callers.

Integration replaced manual iOS download logic in VideoPlayer (removed direct `window.location.href` assignments), simplified DownloadModal's iOS button handler, and unified useDownloadsBatch's iOS path. All existing UI flows (language selection, retry, cancel, progress display) remain unchanged; only the final download trigger was replaced.

Tests cover the complete behavior matrix: platform detection for iOS/Desktop/Android, absolute URL construction from both relative and absolute inputs, progress tracking during downloads, cancellation via AbortController, error handling that distinguishes user cancellation from network failures, and callback invocation (onProgress, onComplete, onError). The iOS absolute URL construction test explicitly mocks `getBackendOrigin()` and verifies the final URL passed to `triggerAttachmentDownload` starts with the backend origin.

## iOS absolute URL construction

The core fix lives in `useUnifiedDownload`'s `buildAbsoluteUrl` helper (lines 116-120). This function detects relative URLs (anything not starting with `http://` or `https://`) and prepends the backend origin from `getBackendOrigin()`. The backend origin returns `https://chillers-production-eace.up.railway.app` in production, resolving the bug where relative paths like `/api/download/file?url=...` would navigate to `https://chillers.site/api/download/file?url=...` (the frontend, which doesn't serve downloads).

The iOS download path (lines 133-161) chains three operations: `toIOSDownloadHref` proxies third-party URLs through the backend's `/api/download/file` endpoint (for Content-Disposition headers), `buildAbsoluteUrl` converts the result to an absolute backend URL, and `triggerAttachmentDownload` opens the URL in a new tab that auto-closes after 2 seconds. The download continues in Safari's background download manager after the tab closes.

Service-layer defense: `toIOSDownloadHref` (line 169 in `downloads.ts`) now explicitly uses `${getBackendOrigin()}/api/download/file?...` when building proxy URLs, eliminating the `API_BASE_PATH` constant that resolved relative to the current domain. `triggerAttachmentDownload` (line 188) converts any relative href to absolute before calling `window.open`. This protects direct callers of the service functions, not just hook users.

Test verification: the "builds absolute URLs for iOS using getBackendOrigin" test (line 95 in test file) mocks `getBackendOrigin()` to return `https://test-backend.railway.app`, passes a relative URL `/api/download/file?url=test`, and asserts `triggerAttachmentDownload` received `https://test-backend.railway.app/api/download/file?url=test`. This confirms the URL construction fix at the behavioral level.

## Platform-specific download paths

iOS downloads are fire-and-forget: the hook calls `triggerAttachmentDownload`, which opens a tab, returns immediately, and the hook optimistically marks complete after 2 seconds (line 156). No progress tracking or cancellation is possible because Safari's download manager runs outside the web page's control.

Desktop and Android downloads use `streamDownloadToDisk` from `streamSaver.ts` (line 179), which streams response bytes through a WritableStream (either Service Worker MITM on Desktop or native Blob download on Android). The hook passes an AbortController signal for cancellation and wires the `onProgress` callback to update internal state (lines 207-215). Progress tracking computes a percentage when total bytes are known, or null for chunked transfers without Content-Length.

## Integration across call sites

VideoPlayer integration (line 282 in `VideoPlayer.tsx`) replaces a complex iOS-specific code path that manually built URLs with `getBackendOrigin()` and assigned to `window.location.href`. The new implementation calls `unifiedDownload.startDownload({ url: directDl, filename })` and delegates all URL construction and platform handling to the hook. This removes 15+ lines of duplication.

DownloadModal integration (line 272 in `DownloadModal.tsx`) replaces an inline call to `triggerAttachmentDownload(href)` with `unifiedDownload.startDownload({ url: dl.task.resolvedUrl, filename })`.

useDownloadsBatch integration (line 344 in `useDownloadsBatch.ts`) replaces iOS-specific logic in the `launchReady` callback. The batch scheduler handles concurrency limits (MAX_CONCURRENT_DOWNLOADS), retry with exponential backoff, and state management; the unified hook handles only the final download trigger.

## Error handling and state management

The hook distinguishes user cancellation from network errors. When `streamDownloadToDisk` throws an AbortError (name === 'AbortError'), the hook resets state without setting an error message (line 245). For other errors, the hook extracts the error message, sets `error` state, and calls the `onError` callback. This prevents "Download canceled" messages from appearing as errors in the UI.

State lifecycle: `startDownload` resets `isDownloading`, `error`, and `progress` before starting (lines 259-261), preventing stale state from a previous download. `cancelDownload` aborts the AbortController and resets all state (lines 298-302). Concurrent download prevention: if `isDownloading` is true when `startDownload` is called, the hook logs a warning and returns early (lines 253-255).

Progress state structure: `{ downloaded: number, total: number | null, percent: number | null }`. The `total` field is null for chunked transfers without Content-Length. The `percent` field is computed as `Math.min(100, Math.round((downloaded / total) * 100))` or null if total is unknown.

## Test coverage comprehensiveness

The test suite (605 lines, 21 test cases) covers the complete behavior matrix: platform detection (iOS vs Desktop/Android), absolute URL construction for relative and absolute inputs, Desktop download path with `streamDownloadToDisk`, progress tracking with percentage calculation, cancellation via AbortController, error handling (network errors vs AbortError), callback invocation (onProgress, onComplete, onError), state management (concurrent downloads, state reset), and iOS-specific behavior (fire-and-forget, no progress).

Critical tests for the iOS fix: "builds absolute URLs for iOS using getBackendOrigin" explicitly mocks `getBackendOrigin()` and verifies the final URL passed to `triggerAttachmentDownload` starts with the backend origin. "converts relative URLs to absolute using backend origin" tests the `buildAbsoluteUrl` helper in isolation. "handles already-absolute URLs correctly" ensures absolute URLs aren't double-prefixed.

Not tested: actual network downloads (would require integration tests with a real backend), Service Worker MITM behavior (tested separately in `streamSaver.ts` tests), Safari's native download manager (requires manual QA on physical iOS devices).
